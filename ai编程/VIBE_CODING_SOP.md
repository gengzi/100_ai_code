# 氛围编程（Vibe Coding）SOP（后端场景版）

目标：在保持高效探索的同时，提高后端 AI 编程的准确性、完善性和可维护性。

## 0. 适用范围
- 适用对象：与 AI 协作进行需求梳理、方案设计、编码实现、评审验证的个人或小团队。
- 适用项目：后端 API 功能迭代、数据模型调整、任务/消息处理、性能优化与故障修复。

## 0.1 实际工作场景示例
- 新增/改造 API：如新增订单创建接口、调整查询过滤与排序。
- 数据库变更：如新增字段、索引优化、迁移脚本与回滚方案。
- 异步任务/消息：如消息消费幂等性、重试与死信处理。
- 外部集成：如对接第三方支付、回调验签与失败重放。

## 1. 核心原则（必须遵守）
1. **需求先行**：任何编码前必须把“要解决的问题”转写为可验证的需求。
2. **最小正确性**：先保证关键路径正确，再扩展边界与完善性。
3. **可维护优先**：可读性、模块化、可测性优先于“炫技”。
4. **变更可追溯**：所有修改可解释、可还原、可审查。
5. **人机协作闭环**：AI 输出必须被人类校验与验证。
6. **线上可控**：优先考虑兼容性、回滚与可观测性。

## 2. 角色分工
- **人类（Owner）**：定义目标与范围，确认取舍与验收标准。
- **AI（Assistant）**：提出方案、编码落地、补齐文档与测试。
- **Reviewer（可选）**：审查接口、边界与风格一致性。

## 3. 流程总览
1. 需求澄清
2. 方案设计
3. 执行计划
4. 编码实现
5. 自检与验证
6. 代码评审
7. 交付与复盘

## 7. 编码实现规范
- **边界先行**：先处理输入校验与错误分支。
- **小步提交**：避免一次性大改；每一步可单独解释。
- **注释策略**：仅在复杂逻辑处添加必要注释。
- **日志与可观测性**：关键路径必须可追踪。
- **一致风格**：遵循现有项目约定与风格。

**后端实现细节**
- **事务清晰**：明确事务边界，避免隐式跨层事务。
- **幂等保障**：通过唯一键/幂等表/请求号处理重复请求。
- **接口兼容**：新增字段保持向后兼容，谨慎移除或改语义。
- **错误语义**：错误码与 HTTP 状态保持一致、可追踪。
- **性能习惯**：避免 N+1、必要时使用分页/游标。
